# ADR-0002：通信与身份

**状态**：已锁定（v1）

## 背景

"这台机器是谁"同时决定谁的成绩算谁的、代码收到哪个目录、下发落到哪、升级包发给谁。
整间机房用**同一份镜像**装出来，所以镜像里带出来的任何东西都**不能**当身份（50 台会带同一身份开机）。
配对必须有人在场：机器注册上来时服务端只知道"有一台机器"，不知道前面站着谁。

## 决定

| 项 | 决定 |
|---|---|
| 认证 | 每机独立 Token，服务端只存 `sha256(token)`，按机吊销 |
| 机器身份 | `machine_uuid`（首选）+ SMBIOS 指纹（快照还原兜底）；`machine_id` **只供人工辨认** |
| 配对 | 镜像统一密钥注册 + **六位数字配对码**绑定到名单条目（**人**）；配对**永久** |
| 关系 | **一人一机、一机一人**，服务端双向强制；覆盖绑定必须走显式「改派」 |
| 场次 | 多场次隔离（`contest_id`）；机器绑人，场次**动态解析** |
| 后台账号 | 单管理员 |
| 网络 | 考场同一内网、双向可达（v1 不用 Ansible，留作备选） |
| 防篡改 | 完整性校验 + 审计日志，**不干预选手** |

- **配对码**：六位数字，只存哈希、限时 30 分钟、一次性、需管理员鉴权；只在绑定那一刻用，之后认机器靠 `machine_uuid`。用六位是因为要人工在屏幕与教师之间传递，"限时 + 一次性 + 管理员鉴权"已压没爆破空间。
- `claimed=false` 的机器**每次 tick 都回发配对码**，所以明文须在服务端**内存**留到过期或配对（库里只有哈希）。

## 后果

- **配对一次，之后 N 场比赛零人工**：换场次、重装、快照还原、升级都不用重配（[`../design/04-server.md`](../design/04-server.md) §4.6）。
- **快照还原自愈**：注册带硬件指纹（还原后不变），服务端据此认回原机；硬前提是**原机当前离线**，因为克隆机报的也是同一指纹。
- 配对码明文只在内存，服务端重启后下次 tick 发新码，桌面文件随之更新。
- 未配对**不另立表**：`agent.roster_entry_id IS NULL`。
- 只有两样凭据：**统一注册密钥**（装机，一次性）与**本机 token**（长期）。**配对码不是凭据**，只是"教师此刻在场"的证明。

## 被否掉的替代方案

* **每选手注册码**（`enroll_code`）：一份镜像装整间机房时逐台发码不可规模化；整条删除而非并存，否则两种模式都要维护、迟早有人选错。`agent.ini` 里残留的 `enroll_code =` 被静默忽略，免得升级上来的机器起不来。
* **`machine_id`（`/etc/machine-id`）当身份**：镜像未通用化时整批相同，等于整批共用一个身份。
* **配对后下发密钥**：机器注册时已拿到凭据，配对只是绑人；多一步只多一处失效点。
* **把 `credential.json` 烤进镜像**：每台克隆机同一身份、互相覆盖且静默，只有成绩对不上人；安装器发现残留身份文件会告警，但那是事后。
* **长配对码 / 字母混合码**：换来熵但易抄错，而安全边界本就不靠它。
* **配对码当每次干活的凭据**："桌面上的码准不准"会变成客户端状态问题，而状态目录最先被快照还原抹掉。
* **多管理员 / 角色权限**：v1 是一间机房一个教师，完整权限模型及其测试面不值得。
