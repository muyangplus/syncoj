# ADR-0004：界面文案口径与考场公告

**状态**：已锁定（v1）

## 背景

管理界面和选手页的用户是**站在机器前面、手上有活要干的人**：教师要在开考前十分钟
把一间机房跑起来，选手要在考试中途知道"几点结束"和"题面在哪"。

界面里曾经长过成段的解释文：为什么这么设计、这两个概念不是一回事、机制怎么运转、
"上传不等于铺开"这类劝告。这些话不错，但**没人能据此动手**；而真正的用户诉求是
"很多功能没有入口"。界面上还出现过 `**已铺开**` 这种 Markdown 语法。

界面上还要有一份教师写给选手看的东西（须知、临时通知）。

## 决定

**页面上禁止声明式/解释式语句。** 允许的只有这几类：

| 允许 | 例子 |
|---|---|
| 标题、标签、按钮、状态、表头、placeholder | 「统一密钥」「已签名」「sha256」 |
| **一句话**操作指引 | 「在每台空机器上跑它。」 |
| **破坏性动作的后果** | 「会删掉统一注册密钥与本机凭据。」 |
| 服务端原文错误、实时数据 | `detail` 直接显示，不加工成第二种说法 |

判断标准是**"站在机器前面的人此刻能不能据此动手"**，而不是"这句话有没有用"：
不能据此动手的解释句一律删掉，能据此动手的后果句留下（后果句少了更危险 ——
删东西之前必须让人知道会丢什么）。

**考场公告就是一份下发的 `NOTICE.md`**，不另设公告字段。判据是本场 + 发给他本人的
下发记录里 basename 大小写不敏感地匹配 `notice.md`，多份就取最后下发的那一份；
非 UTF-8 与超过 64 KB 的跳过并记一条日志。

选手页从上到下是**场次卡 → 考场公告 → 下发文件**；公告排在**场次标题下面**而不是
页面最顶上。正文按 **Markdown 渲染**（`marked` + `DOMPurify`），开 `breaks: true`。

## 后果

- 有一条 AST 守卫：面向用户的字符串里不许出现 Markdown 标记
  （`server/tests/test_errors.py` 那一套连同前端文案一起把关）。
- 公告不另设字段，所以公告和别的下发文件本来就是同一件事 ——
  教师写一遍、下发一次，不存在"哪个作数"的问题。
- 公告随下发记录走，所以**本场 + 发给他本人**这个范围是免费的。
- `breaks: true` 是必须的：公告是在一个纯文本框里写出来的，写的人未必在想 Markdown
  语法 —— 他写下两行、就该看到两行。关掉它等于把上一版 `pre-wrap` 的保证偷偷去掉，
  而症状（"我一行一条写的，显示成一整句了"）只会被当成"渲染错了"。

## 被否掉的替代方案与理由

* **在页面上写解释**。"为什么这么设计""这两个概念不是一回事"读起来有用，但读者
  此刻要的是下一步动作；而解释句会**挤掉**动作入口 —— 那是"很多功能没有入口"
  的成因之一。解释属于文档，不属于界面。
* **"上传不等于铺开"这类劝告**。它不是动作、也不是后果，只是一句提醒；
  真正需要的护栏是"只建草稿，铺开仍是单独的、显式的一步"。
* **单独加一个"公告字段"**。等于让教师写两遍，还要额外解释"哪个作数"；
  而下发链路本来就要把文件送到每台机器。
* **不用 Markdown、原样显示公告正文**。当时的理由是"为一段公告装一个 Markdown 库
  不值得，`##` 也看得懂"；这条理由已被现场推翻 —— 教师写的就是 Markdown，
  原样显示是一堆符号，而"公告没排过版"会被当成系统不认真。
* **渲染但不消毒**。正文是教师从别处粘进来的，`<img onerror=…>` 这类东西会把考场
  机器上的这一页变成任意脚本的宿主。
* **用 URL 参数预填"手填场次 + 考号"那个兜底入口**。那会让"这一页显示的是谁"
  取决于一个可以被随手改的链接。
* **从题目模式推导"保存规则"给选手看**。服务端不知道每台机器的 `scan.roots` 与
  文件名前缀，推导出来的"把代码存到 X"很容易是错的 —— 而一条错的操作指引比没有
  指引更坏。
