# ADR-0004：界面文案口径与考场公告

**状态**：已锁定（v1）

## 背景

管理界面与选手页的用户是**站在机器前、手上有活的人**：教师要在开考前十分钟把机房跑起来，选手要知道几点结束、题面在哪。
界面里成段的解释文（设计理由、概念辨析、机制、"上传不等于铺开"这类劝告）没人能据此动手，还挤掉了动作入口（用户反馈"很多功能没有入口"）；界面上也出现过 `**已铺开**` 这种 Markdown 语法。
另外需要一份教师写给选手的东西（须知、临时通知）。

## 决定

**页面禁止声明式/解释式语句**，只允许：

| 允许 | 例子 |
|---|---|
| 标题、标签、按钮、状态、表头、placeholder | 「统一密钥」「已签名」「sha256」 |
| **一句话**操作指引 | 「在每台空机器上跑它。」 |
| **破坏性动作的后果** | 「会删掉统一注册密钥与本机凭据。」 |
| 服务端原文错误、实时数据 | `detail` 直接显示，不加工成第二种说法 |

判据是**站在机器前的人此刻能否据此动手**：不能动手的解释句删，能动手的后果句留（删东西前必须让人知道会丢什么）。

**考场公告就是一份下发的 `NOTICE.md`**，不另设字段：本场 + 发给他本人的下发记录里 basename 大小写不敏感匹配 `notice.md`，多份取最后下发的；非 UTF-8 或超过 64 KB 的跳过并记日志。
选手页顺序 **场次卡 → 考场公告 → 下发文件**（公告在场次标题下）。正文按 **Markdown 渲染**（`marked` + `DOMPurify`），开 `breaks: true`。

## 后果

- AST 守卫：面向用户的字符串不许出现 Markdown 标记（`server/tests/test_errors.py` 连同前端文案）。
- 公告与其他下发文件是同一件事：写一遍、发一次，不存在"哪个作数"；**本场 + 发给本人**的范围随下发记录自动得到。
- `breaks: true` 必须开：公告写在纯文本框里，写两行就该看到两行，否则会被当成"渲染错了"。

## 被否掉的替代方案

* **页面上写解释**：读者此刻要的是下一步动作，解释句会挤掉动作入口；解释属于文档。
* **"上传不等于铺开"这类劝告**：既非动作也非后果；真正的护栏是"只建草稿，铺开是单独的显式一步"。
* **单独的公告字段**：教师要写两遍，还要解释哪个作数；下发链路本就会把文件送到每台机器。
* **不渲染 Markdown、原样显示**：教师写的就是 Markdown，原样显示是一堆符号，会被当成系统不认真。
* **渲染但不消毒**：正文常从别处粘贴，`<img onerror=…>` 会让考场机器上这页执行任意脚本。
* **URL 参数预填"手填场次 + 考号"兜底入口**："显示的是谁"会取决于一个可随手改的链接。
* **从题目模式推导"保存规则"给选手看**：服务端不知道每台机器的 `scan.roots` 与前缀，错的操作指引比没有更坏。
