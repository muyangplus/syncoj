# ADR-0005：公开端口

**状态**：已锁定（v1）

## 背景

考场机器上的地址是教师**说给学生听**的。`http://10.0.0.5/` 这种地址好念，
`http://10.0.0.5:8000/` 难念，而浏览器对 http 默认走 80，连端口都不用敲。

但管理界面和全部 API 也在同一套进程里。如果让学生敲进同一个端口，他们看到的是
**一个登录框和一张接口地图** —— `/docs` 不需要登录就能列出全部管理接口。

## 决定

服务端**默认再开一个监听**（`SYNCOJ_PUBLIC_PORT`，默认 80）：

| 端口 | 上面有什么 |
|---|---|
| `--port`（默认 8000） | 全部：管理界面 + 三套 API + `/docs` |
| `SYNCOJ_PUBLIC_PORT`（默认 80） | 只有 `/install` 与 `/player`；管理端、`/docs`、`/openapi.json`、`/healthz` 一律 404 |

几条一起定下来的细节：

- `SYNCOJ_PUBLIC_PORT=0` 关掉第二个监听（`0` 是哨兵：留空等于没设，会退回默认的 80）。
- 门禁是**黑名单**（挡 `/api/v1/admin`、`/docs`、`/redoc`、`/openapi.json`、`/healthz`），
  不是"只放行这两页的白名单"。
- 被挡掉的接口回 **404 而不是 403**。
- "这个请求是从公开端口进来的吗"由服务端**启动时**写进 `app.state.public_port`，
  判据是"真的在那个端口上听着"，不是配置里写的数字。
- 前端由服务端在公开端口的 `index.html` 里注入
  `window.__SYNCOJ__={"publicOnly":true,"adminPort":8000}`（见 `web/src/publicMode.ts`），
  据此把默认路由和兜底路由都压到 `/player`，并且**不去碰鉴权状态**。

## 后果

- 绑不上 80 时服务端会**降级**（只留管理端口并打印两种修法）—— 而"是否公开端口"
  取的是实际监听状态，所以降级之后 **80 上没有任何监听，也就不该有请求被当成公开
  端口**；否则一台绑不上特权端口的服务端会顺带把自己的管理界面一起关掉，而现场只看
  到"管理界面 404"。
- 判据取"实际监听"还有一个副作用：`TestClient` 的默认地址端口恰好就是 80。
  判据若取配置默认值，整个既有测试套件会在一瞬间全部被误判成"来自公开端口"。
- 注入里的 `adminPort` 是给**装机命令**用的：命令里那个地址会被写进那台机器的配置、
  从此长期使用，所以它必须指向 API 端口，而不是教师恰好打开的那一页所在的端口 ——
  公开端口是个"方便用的"端口，可以关掉。主页名仍取当前页面的
  （那是"从局域网真的可达"的真人证据，见 [`../design/07-ops-and-install.md`](../design/07-ops-and-install.md) §7.3）。
- 不让学生自己数端口：http 的 80 在浏览器里 `location.port === ""`，
  而且那等于把同一个事实定义两遍。

## 被否掉的替代方案与理由

* **同一个端口按路径分**。那样学生敲进来的这个原点上就有登录框，还有一张接口地图 ——
  `/docs` 不需要登录就能列出全部管理接口。
* **"只放行这两页"的白名单门禁**。白名单漏一条的后果是**这两页悄悄坏掉**
  （现场看到的是白屏、转圈或一段 HTML，没人会想到是端口门禁干的）；黑名单漏一条的
  后果只是多暴露一个接口，而那些接口自己还有 `require_admin` 兜着。两侧都会漏时，
  宁可漏在"多一道鉴权门"那一侧。
* **403 而不是 404**。403 等于顺手指路"管理接口在别处，去另一个端口试试"。
* **判据取配置里的端口号**。见上：降级之后事实与配置不一致，而且会和 `TestClient`
  的默认端口撞车。
* **换一个非特权端口给考场机器（比如 8080）**。它要学生多敲四个字符，而这些字符
  是从教师嘴里传过去的 —— 一个考点一上午会有几十次这个传递，每次都多一次出错机会。
* **前后端各数一遍端口**。http 的 80 在 `location.port` 上是空字符串，前端数不对；
  而且那是把同一个事实定义两遍。
