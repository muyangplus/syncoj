# ADR-0006：验收不许拿自己人替代

**状态**：已锁定（v1）

## 背景

两处"自己验自己"的诱惑：

1. **升级包的信任锚**：`.key/` 里的私钥与公钥构建时读一次、验收时再读一次，那么"那对文件是否配套""公钥是否**真的内嵌进包**""签名对象到底是什么"在验收里都不会暴露。
2. **手写的密码学代码**：Agent 零依赖（[ADR-0001](ADR-0001-tech-stack-and-dependencies.md)），RSA 验签是手写的，自签自验永远能过。

共同点：验证者与被验证者共用同一份实现或假设，错误会**同时**出现在两边，测试恒绿。

## 决定

**验收链路里不许出现"再实现一遍"的中间结果。**

- 升级链路整条跑：构建 → 签发 → 铺开 → 从**面向 Agent 的接口**下载 → **Agent 自己的** `verify_bundle` 验签验摘要 → `safe_extract_tar` 解开，全程用目标机会跑的那份代码。
- 信任锚取**包里内嵌的那份**，不从密钥目录再读。
- 手写 RSA 的正确性证据来自 **openssl 交叉验证**：签名与 openssl 逐字节相同，openssl 的签名本代码能验。签名对象是规范化文本 `syncoj-release-v1\n<版本>\n<sha256>\n<字节数>\n`（版本号纳入签名，见 [`../design/06-security.md`](../design/06-security.md)），不是包字节。
- 校验**严格**：整体重建 `EM` 后比较，不做"解析出 hash 再比对"。
- 路径安全校验服务端与 Agent（`agent/syncoj_agent/safepath.py`）**各自独立实现**，一致性由 `test_path_validation_parity` 守住。
- 前端类型绝不手写，从 OpenAPI 生成。

## 后果

- `server/tests/test_release_build.py` 最要紧的一条**不查任何中间结果**，只跑整条链；「`.key/` 那对文件是否配套」「公钥是否真的内嵌」「签名对象是否为 `release_signing_message` 文本」任一错都会红。
- openssl 交叉验证要求 **openssl 1.1.1 与 3.0 两种默认输出格式**都能读，否则等于把验签失败甩给对方版本。

## 被否掉的替代方案

* **验收时从 `.key/` 再读公钥**："公钥有没有内嵌"永远测不到，而它错的表现是发版、铺开都成功，**所有机器一动不动**，最难查。
* **测试里再写一遍验签**（再实现 `pow(sig, e, n)`）：测试与被测代码犯同一个错，"两边一致"被当成"两边都对"。
* **Ed25519**（原定）：Python 3.8 标准库没有非对称签名原语，用它须引入 `cryptography`/`pynacl`，违背零依赖；RSA 验证只需 `pow(sig, 65537, n)` + 字节比较，手写风险低得多。
* **宽松校验**（解析出 hash 就通过）：PKCS#1 v1.5 的历史伪造攻击（Bleichenbacher 2006 等）全部源于此。
* **纯 Python 生成密钥**：Miller-Rabin 与随机素数搜索极易写错，而这是一次性管理操作，调 `openssl` 可接受。
* **信任锚改用配置里的路径**：把"包里那份"换成"服务端手边那份"，两者不同步时机器一律拒收，现场只见"升级没生效"。
