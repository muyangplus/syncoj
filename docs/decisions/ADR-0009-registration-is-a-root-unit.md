# ADR-0009：注册由 root 的一次性单元做，服务本体永不自己注册

**状态**：已锁定（v1，真机踩坑后补上）

## 背景

**真机上踩过：机器永远不出现。**

统一注册密钥是 `/etc/syncoj/bootstrap.key`、**0600、属主 root** —— 这是故意的，
因为它能注册整间机房。而 `syncoj-agent.service` 以**运行账号**（选手）跑，
**读不到它**。

当时的分工是让服务本体"顺手试一下"注册。于是：

```
读密钥 → PermissionError → 抛异常 → 退出 1
  → systemd 按 RestartSec=5 反复重启
  → 5 次后撞上 StartLimit，罢手
  → 而注册单元从来没被跑过
```

现场看到的是"服务反复重启"或者干脆"什么都没有"，
而真正的原因（注册那一步没做）不在任何一条日志里。

## 决定

**两个单元，分工写死，不能混：**

| 单元 | 身份 | 干什么 |
|---|---|---|
| `syncoj-agent-enroll.service` | **root**（oneshot；装机时 enable，并立刻跑一次） | 读 `/etc/syncoj/bootstrap.key`，换回本机凭据，写进状态目录并交给运行账号 |
| `syncoj-agent.service` | **运行账号**（= 跑安装的那个账号） | 只读凭据干活；**没有凭据就等**，绝不自己去读那把密钥 |

**服务在拿到凭据之前只做一件事：安静地等**（每 `REGISTRATION_POLL_SECONDS` 看一眼
凭据是否出现），并把"下一步该看哪个单元"写进日志。

**"服务不自己注册"这条不能松** —— 它同时也是"选手账号拿不到注册密钥"的保证。

## 后果

- 密钥是 root 只读的，而服务以选手身份跑**读不到它**（这是设计如此）。
  所以"服务自己注册"必然失败，而失败的表现是"机器永远不出现"。
- 排障时第一眼看**注册单元**：`systemctl status syncoj-agent-enroll.service`
  与 `journalctl -u syncoj-agent-enroll.service -n 30`。
- `Start request repeated too quickly` 说明 systemd 已经罢手：先修掉真正的错误，
  再 `systemctl reset-failed syncoj-agent`，然后按顺序起注册单元、再起服务。
- 注册失败的原文都在注册单元的 journal 里（密钥被吊销、还没配对、
  `agent.ini` 属主不对、被限速、扫描目录的父目录不存在…），排障表见
  [`../install-agent.md`](../install-agent.md)。
- 代价：装完之后机器上多一个单元，而"注册成功没有"这件事变成一次性的 ——
  之后服务重启不会再注册（它只读凭据）。重新注册要显式跑那个单元。

## 被否掉的替代方案与理由

* **服务本体自己注册**（用 root 跑服务，或者服务里 `sudo` 一下）。见背景：
  它是那次真机事故的成因。而且它会顺带毁掉"选手账号拿不到注册密钥"这条保证 ——
  那把密钥能注册整间机房。
* **把密钥的权限放宽到选手可读**。那就等于把"能注册整间机房"的通行证放在学生
  读得到的文件里。`agent.ini` 是 chown 给选手账号的，密钥放进去等于公开 ——
  这是安装时最容易犯的三个错之一。
* **把密钥写进 `agent.ini`**。同上；而且 `agent.ini` 会随逐键策略被覆盖/合并，
  密钥在里面还可能被某次 `config_policy` 改动冲掉。
* **服务在没凭据时直接失败退出**（退出码非 0 让 systemd 提醒）。表现是刷屏 +
  撞 `StartLimit` 之后彻底罢手，而**真正该做的那件事（跑注册单元）还是没人知道**。
  现在"安静地等"并且把下一步写进日志，现场按指引一条命令就能修好。
* **注册单元用 `Restart=`**。见 [ADR-0008](ADR-0008-systemd-unit-hardening.md)：
  oneshot 的重启语义跨版本不一致，有限重试写在 `ExecStart` 的 shell 循环里更可控。
* **一次性注册改成每次开机都注册**。每台机器的凭据会随整机还原消失，
  所以"重新注册"确实要能发生 —— 但那是**明确的、有意的**动作（跑那个单元），
  不是每次开机都去动一遍凭据。
