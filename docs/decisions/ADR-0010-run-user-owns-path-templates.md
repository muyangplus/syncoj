# ADR-0010：`{home}` / `{desktop}` 恒按**运行账号**展开

**状态**：已锁定（v1，真机故障后补上）

## 背景

Agent 配置支持路径模板（`scan.roots = {desktop}/{player_no}`、`deploy_root = {desktop}`），问题是展开成**哪个用户**的家目录。

真机故障：注册单元以 **root** 跑，按当前进程用户展开得到不存在的 `/root/桌面`，配置校验失败、注册退出 2；journal 只报"扫描目录的父目录不存在"，表现是机器永远不出现。
另外，执行安装的账号不一定是将来跑 Agent 的账号，跨用户授权在现场易装成"服务起来了但什么都不传"。

## 决定

- **`{home}` / `{desktop}` 恒按运行账号解析**（`[agent] run_user`），与当前进程是谁无关。
- **运行账号默认 = 执行安装的账号**（显式 `--user` 才建专用账号），安装器把它写进 `run_user`；`run_user` 留空退回当前用户（手工部署、排障用）。
- `{desktop}` 探测：先读 `<运行账号的家>/.config/user-dirs.dirs` 的 `XDG_DESKTOP_DIR`，再试 `~/桌面`、`~/Desktop`、`~/desktop`。
- `{desktop}` / `{home}` **载入配置时展开**；`{player_no}` / `{contest_slug}` **注册拿到凭据后展开**，之前原样保留不报错；注册后 Agent 在启动日志打出最终目录。

## 后果

- 注册单元以 root 跑也解析到运行账号的桌面，绝不落到 `/root`。
- 状态目录属主跟随运行账号（`agent.ini` 与状态目录文件都 chown 给它）；漏 chown 表现为"装完起不来"或"一直重新注册"，报的是权限错，所以安装器会检查并告警。
- 注册单元以 root 跑，所以安装器**必须**写入 `run_user`，否则退回 `/root`，回到原故障。
- 单元不能设 `ProtectHome=read-only`（[ADR-0008](ADR-0008-systemd-unit-hardening.md)），因为 Agent 要往该桌面写配对码。

## 被否掉的替代方案

* **按当前进程用户展开**：注册单元是 root，展开成 `/root/桌面`，失败且报错指不到原因。
* **强制专用账号 `syncoj`**：其家目录与选手桌面是两个地方，选手不会去那里写代码；跨用户授权易装成"什么都不传"。
* **探测"当前登录的图形用户"**：开机自启时常无人登录，`who`/xdotool 类判据给不出答案；"运行账号"任何时候都成立。
* **展开不了就报错**：校验在注册前，`{player_no}` 本就无值，会把"还没注册"误报成"配置错了"。
* **只认 `~/Desktop`**：中文 NOI Linux 上是「桌面」；先读 `user-dirs.dirs` 再逐个试才对。
* **状态目录放运行账号家目录下**：root 写（注册单元写凭据）与运行账号读的权限边界会含糊；`/var/lib/syncoj` + chown 更直白。
