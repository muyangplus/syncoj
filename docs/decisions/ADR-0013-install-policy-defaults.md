# ADR-0013：安装策略三条的默认值

**状态**：已锁定（v1，真机故障后补上）

## 背景

"发一次版"不只是换程序，还要决定**机器上已有的东西要不要跟着改**。同一个包发给
不同机器，要求可能不同：

* "这次是重装，包里那把密钥必须覆盖机器上已经吊销的旧钥"
* "这台机器是教师手工配过的，别动它"

这些决定收在构建卡片的**高级选项**里，**随包（以及装机台账、升级清单）带下去**，
字段名冻结。它们必须出现在三个地方（装机台账、升级清单、离线包根目录下的
`install_policy.json`），**同一份真相只能有一个出口** —— 三大各写一遍必然漂移，
而漂移的方式还特别难查：机器按 A 处给的策略装机、按 B 处给的策略升级。

**真机故障**：真机被"机器上躺着一把**已吊销的旧钥**、包内的新钥用不上"坑到，
机器永远注册不上。

## 决定

| 字段 | 取值 | 默认 | 管什么 |
|---|---|---|---|
| `bootstrap_key_policy` | `keep` / `replace` | **随包内有没有密钥**：带 → `replace`，不带 → 忽略 | 机器上已有的统一注册密钥要不要被包内那把覆盖 |
| `config_policy` | `{"<section>.<key>": "keep"｜"default"｜"force"}` | 全部 `keep` | 机器上 `agent.ini` 的**逐键**更新策略 |
| `upgrade_mode` | `apply` / `stage` / `off` | `apply` | 拿到新版本后：自动切换重启 / 只下载验签 / 不动 |

三条默认值的理由：

- **`bootstrap_key_policy` 默认 `replace`（勾了"附带密钥"时）**：见背景。替换是不可逆
  的，所以安装器**先把旧的那把备份**（`bootstrap.key.replaced-<时间戳>`，0600 root）
  并在回执里写明备份路径与旧钥指纹。显式 `--bootstrap-key` 永远优先级最高。
- **`config_policy` 默认全部 `keep`**：`agent.ini` 里的扫描根、下发根、服务端地址都是
  **现场数据**，默认不动是唯一安全的起点。三态语义（`keep` / `default` / `force`）、
  快照文件与作用域边界见
  [`../design/07-ops-and-install.md §7.2.1`](../design/07-ops-and-install.md)。
- **`upgrade_mode` 默认 `apply`** 是产品决定："机器上正在跑的进程默认自动更新、
  切换新版本、自动重启"。**但有一个必须的例外：镜像/包里没有发布公钥时降级成 `off`
  并明确说出来** —— 没有信任锚的机器根本验不了包，若还按 `apply` 走，`validate()`
  会直接报错、服务起不来，表现是**整批机器失联**。显式写 `apply` 却没有公钥仍然是
  **硬错误**（那是配置错误，不是默认值问题）。

**优先级**：显式 CLI 参数 > 服务端台账 > 包内 `install_policy.json` > 模板默认。
"台账 > 包内"的理由是：在线装机时台账是服务端**此刻**的真相，而包可能是几天前打的。

## 后果

- `config_policy` 的键名有**规范清单**（`CONFIG_POLICY_KEYS`），必须与
  `agent/config.example.ini` 逐键对得上。多一个：教师能配一条**安装器不会写**的键，
  界面显示配好了、机器上什么都没发生。少一个：某个键永远没法被逐键覆盖，
  而没有任何地方会提示这件事。逐键说明见
  [`../reference/config-keys.md`](../reference/config-keys.md)。
- **已知边界（不是缺陷，是划界）**：这三条策略**只在装机时生效**。自升级（运行账号
  跑的那条路）只换程序，**不改 `agent.ini`、也不动注册密钥** —— 注册密钥是 root 只读，
  运行账号无论如何改不了。要改配置或换密钥，就**重跑安装器**（它有 root）。
  这条写下来是为了让它是"划的界"，而不是某天被当成 bug 去"修"。
- 升级模式默认 `apply` 的前提是"Agent 装在版本化目录 + `current` 软链布局下"，
  否则 apply 无处可切，会直接失败。

## 被否掉的替代方案与理由

* **`bootstrap_key_policy` 默认 `keep`**。听起来更"安全"，但真机上正是它导致了
  "机器上躺着一把已吊销的旧钥、包内的新钥用不上、机器永远注册不上"。
  而 `replace` 的不可逆性用**先备份 + 回执写明备份路径与旧钥指纹**兜住了。
* **`upgrade_mode` 默认 `off`（考场更稳）**。机器铺开之后**没人会一台台点升级**，
  默认不升就等于这套自更新功能在大多数考点上不会被用到。
* **没有公钥时静默按 `default`/`off` 处理、不报错**。那会让"显式写了 `apply`
  却没有公钥"这种配置错误变成一个静默降级 —— 而它本该被大声报出来。
* **让自升级同时改配置**。"升级过程中改自己的配置再重启"是一类新的、影响面很大的
  语义，而运行账号本来也改不了 root 只读的密钥。要改就重跑安装器。
