# ADR-0015：服务端主动通告只当线索，切换前挑战应答

**状态**：已锁定（v1，2026-11）

## 背景

机器找服务端原来只有一个方向：包内嵌地址，找不到就机器自己在局域网里广播探测、服务端
签名应答（ADR 与 §7.3）。服务端换了 IP 时，每台机器要连续失败若干轮才去问，50 台机器
陆续转过来要半分钟以上。提议是反过来：服务端上线时喊一声，机器听到就响应。

## 决定

1. **服务端周期通告**（前 10 分钟每 30 秒、之后每 5 分钟，加管理端「召集机器」），UDP 45872。
2. **通告不签名**，机器只把它当线索；切换前到通告里的地址上做**挑战应答**
   （`GET /api/v1/agent/whoami?nonce=`，不带凭据），用发布公钥验签。
3. 服务端签的是**它自己认定的**对外地址，机器切换到**签名里**的地址。
4. 机器自己探测的那条路**保留，阈值不变**。

## 后果

* 机器第一次对局域网开放一个监听端口：输入按不可信处理（限长、只认几个键、`key_id` 过滤、
  `boot_id` 去重、每分钟最多认真处理一次），处理结果至多是"去某个地址 GET 一个固定路径、
  不带凭据"。
* `whoami` 是不鉴权的签名端点，按来源 IP 限速。
* 在 ufw 默认策略、广播被隔离的机房里，通告完全收不到 —— 那里的行为与以前一样。

## 被否掉的替代方案

* **给通告签名、机器验过就切**：单方面发出的报文没有机器给的随机数，挡不住重放 —— 录下一条
  真通告，等那个 IP 被 DHCP 分给别的机器再放出来，50 台机器就会把统一注册密钥送过去。
  带时间戳要求考试机时钟准，还原卡机房的时钟常差几小时。
* **切到通告里的地址（而不是签名里的）**：有人把挑战请求转发给真服务端，就能用真签名把机器
  引到自己那里。
* **删掉机器自己探测、"不主动扫描"**：开机晚于通告的机器要干等下一次通告；ufw 挡入站 UDP 的
  机房里通告完全失效；装机时安装器等不到通告却必须当场拿到地址。
* **放宽机器探测阈值**：同上，收不到通告的机房只会因此变慢。
