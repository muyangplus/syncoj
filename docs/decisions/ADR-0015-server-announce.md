# ADR-0015：服务端主动通告只当线索，切换前挑战应答

**状态**：已锁定（v1，2026-11）

## 背景

- 原有方式只有一个方向：包内嵌地址；找不到时机器广播探测、服务端签名应答（§7.3）。
- 服务端换 IP 后，每台机器须连续失败若干轮才探测，50 台全部转过来需半分钟以上。

## 决定

1. **服务端周期通告**（前 10 分钟每 30 秒、之后每 5 分钟；另有「机器配对」→「召集机器」与顶栏「快捷操作」→「召集机器」），UDP 45872。
2. **通告不签名**，机器只当线索；切换前到通告里的地址做**挑战应答**（`GET /api/v1/agent/whoami?nonce=`，不带凭据），用发布公钥验签。
3. 服务端签**它自己认定的**对外地址，机器切到**签名里**的地址。
4. 机器自己探测的路**保留，阈值不变**。

## 后果

* 机器对局域网开放一个监听端口，输入按不可信处理（限长、只认固定键、`key_id` 过滤、`boot_id` 去重、每分钟最多处理一次）；最坏结果是"去某地址 GET 一个固定路径、不带凭据"。
* `whoami` 是不鉴权的签名端点，按来源 IP 限速。
* ufw 默认策略或广播被隔离的机房收不到通告，行为不变。

## 被否掉的替代方案

* **给通告签名、验过就切**：单方面报文无机器随机数，挡不住重放（录下真通告，待该 IP 被 DHCP 分给他人再放出，机器会送出统一注册密钥）；加时间戳则要求考试机时钟准确，还原卡机房常差几小时。
* **切到通告里的地址而非签名里的**：把挑战请求转发给真服务端即可用真签名把机器引走。
* **删掉机器探测**：开机晚于通告的机器须等待；ufw 挡入站 UDP 的机房通告失效；装机时安装器须当场拿到地址。
* **放宽机器探测阈值**：收不到通告的机房变慢。
