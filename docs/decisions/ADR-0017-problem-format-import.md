# ADR-0017：题目配置导入导出折算成现有数据包，模型只加 IO 文件名两列

**状态**：已锁定（v1，2026-11）；扩充 [ADR-0016](ADR-0016-builtin-judge.md) 的数据包约定。

## 背景

- 教师手里的题目来自 LemonLime 比赛目录、HOJ / Hydro / QDUOJ 导出包、FPS XML，原来只能逐题手工整理数据包、再在「设置」里填时空限制。
- 各格式的评测语义比 SyncOJ 多：逐点限制、子任务依赖、sum / max / average 子任务、小数分、栈限制、交互题。
- 约束：评测机、`runner.py`、成绩格式与前端已按 §12.5 的数据包语义上线；服务端零额外依赖（ADR-0001）。

## 决定

1. 每道外来题目规整成 §12.5 的数据包，走与上传数据包相同的 `parse_testdata` 校验与 blob 存储；评测与计分不改。
2. 题目模型只加 `input_file` / `output_file` 两列（文件 IO 名与 ident 不同在 Lemon、HOJ、Hydro 里很常见，改 ident 会动收代码的文件名与成绩列）。其余差异折算并逐题警告：逐点 / 逐组限制取最大值，依赖丢弃，max / mul 按捆绑，average 拆点，小数分向下取整，栈限制丢弃。
3. YAML 用自带的受限子集解析器 `yaml_lite`，不支持的写法报错。
4. 随仓库带 testlib.h（MIT），checker 用了而包里没有时补上；实数比较与 HUSTOJ spj 外壳由服务端生成。
5. 导出 SyncOJ 原生（无损）、HOJ、LemonLime、Hydro；QDUOJ 与 FPS 只导入。

## 后果

* 外来题目导入后的评分可能与来源平台不同；每条差异都在预览里逐题列出，教师按需改数据或跳过。
* 导出到其他平台也会丢语义（编译参数、IO 文件名、0 分点在 Hydro 中被补分等），导出预览逐题列出。
* 新老评测机须一起升级：老评测机忽略 IO 文件名两列。

## 被否掉的替代方案

* **支持逐点 / 逐组时限与内存**：要同时改数据包结构、`runner.py`、评测机报文与前端；NOI 风格题目绝大多数整题统一限制。
* **支持子任务依赖与 sum / max 计分策略**：同上，且依赖的语义各平台不一致。
* **小数分**：成绩矩阵、手工补录、CSV 导出都按整数分设计。
* **引入 PyYAML**：多一个运行时依赖只为读 Hydro 配置；Hydro 实际写出的 YAML 只用到一个小子集。
* **QDUOJ / FPS 导出**：两者表达不了捆绑子任务、testlib checker 与文件 IO，导出必然丢语义。
* **checker 部分分（退出码 7）、交互 / 通信 / 提交答案题**：需要新的评测流程，单独立项。
