# ADR-0018：一台机器绑多份名单

**状态**：已锁定（2026-11）；修订 [ADR-0002](ADR-0002-communication-and-identity.md) 的"一机一人"

## 背景

- 同一间机房要轮流服务多份名单：班级名单、考场名单、集训名单，各自编考号。
- ADR-0002 的单值绑定（`agent.roster_entry_id`）让一台机器只能属于一份名单里的一个人；换一份名单就要整间机房重新配对。
- 曾经"一人一机"按**考号**跨名单查重：两份名单考号各自编号时，名单 A 的 1 号与名单 B 的 1 号是两个人，却被当成同一个人互相挡住。

## 决定

| 项 | 决定 |
|---|---|
| 结构 | 新表 `agent_binding(agent_id, roster_entry_id, roster_id)`；唯一约束 `(agent_id, roster_id)`、`(roster_entry_id)`；`agent.roster_entry_id` 删除（迁移 021 搬迁） |
| 场次取人 | 用**场次所用名单**（`default_roster_id`）里的那条绑定；场次没指定名单时按考号对应，但多个考号同在或考号被别的机器绑着时不猜 |
| 配对 / 改派 / 解绑 | 只动目标所在的那份名单；解绑可指定名单或全部 |
| 智能匹配 | 同名（去首尾空白 + NFKC）建议，重名用座位号 / 考号收窄，仍不唯一不建议；名单级批量先预览、确认后逐对校验应用 |

## 后果

- 新场次换了名单时不必逐台配对：对那份名单「按姓名匹配机器」一次。
- 场次指定了名单后，机器只有在那份名单里绑着才进这一场 —— 升级前只绑了班级名单、场次默认名单却是考场名单的机器，要先做一次「按姓名匹配机器」。
- 场次没指定名单时，同一考号被两台机器在不同名单里绑着，两台都不进这一场（请给场次指定名单）。

## 被否掉的替代方案

* **保留 `agent.roster_entry_id` 当"主绑定"、新表只放额外绑定**：两份真相，每个写路径都要同步，哪份说了算只能靠约定。
* **一人一机继续按考号跨名单查重**：与"各名单考号各自编号"矛盾；两台机器写同一目录的风险改由场次取人规则（只认场次名单的那条绑定）消除。
* **场次没绑名单的机器按考号兜底进场**：名单 A 的 1 号会落到名单 B 的 1 号（另一个人）的目录里，而且完全静默。
* **同名自动绑定、不经确认**：同名不等于同一人；批量绑错的后果是代码与成绩归属整体错位。
