## 5. 接口约定与前端

### 5.1 协议一致性靠契约测试，不靠共享模型

Agent 零依赖，**不能 import pydantic**。所以一致性不靠共享模型，靠 **CI 契约测试**：

```python
# server/tests/test_agent_contract.py
def test_tick_payload_matches_schema():
    raw = subprocess.run(["python3", "agent/tools/build_fixture.py"],
                         capture_output=True, text=True).stdout
    TickRequest.model_validate(json.loads(raw))     # 不匹配就红
```

`agent/tools/build_fixture.py` 用 Agent 自己的纯标准库构造器生成真实 payload。
服务端 schema 一改、契约一破，CI 立刻拦住。

### 5.2 管理端 API：一个信封、一个错误体

完整约定见 [`docs/reference/api-conventions.md`](../reference/api-conventions.md)。两句话概括：

```jsonc
// 所有列表
{ "items": [ … ], "total": 137, "limit": 50, "offset": 0 }

// 所有错误
{ "detail": "这句是给人看的中文", "code": "roster_entry_taken", "details": { } }
```

改这一层的真实原因：这一轮之前，同一件事在 74 个接口里有好几套写法 ——
列表有的裸数组、有的带 `items`；错误的 `detail` 有时是字符串、有时是对象、
422 又是 pydantic 的英文结构，前端只能逐个接口写适配，于是"少写一个入口"和
"这个接口忘了处理"成了常态。约定的价值不在好看，在于**前端能写一次数据层**。

两条具体规则值得单独说：

- **`detail` 永远是字符串**，而且是一句能直接贴到提示条上的中文；
  422 由处理器揉成"每页条数太大了（最大 500）；考号不能为空"，原始错误列表
  留在 `details.errors` 里给表单标红框用。
- **500 必须有兜底处理器**。没有它时 Starlette 返回纯文本 `Internal Server
  Error`，前端 `response.json()` 当场抛 `SyntaxError`，界面上显示的是
  "Unexpected token I" 而不是任何有用的东西。
- **码表要能被静态检查**。`ERROR_CODES` 是唯一清单，`CODE_BY_STATUS` 是"没显式
  给码时按状态码推"的兜底表，四条规矩（发出的码必须登记 / 登记的必须真会发出 /
  兜底码必须登记 / 用得到的状态码必须有兜底）全部由 AST 扫描守着，不是靠人记得。
  这不是洁癖：写这套检查的当下就抓出两个真问题 —— 410 有三个接口在用（"该版本
  已撤回"就在其中）却没有兜底码，于是这类响应带的是毫无含义的 `code: "error"`；
  而 400 的兜底码 `bad_request` 根本没登记，也就是说**最常见的错误状态是唯一
  没有文档的那种**。反面同样抓出 8 个登记了却永远发不出来的码（`contest_frozen`、
  `roster_in_use`、`last_admin` …），它们描述的是设计时想象中的场景，而对应的
  校验要么不存在、要么当初就选了更宽容的做法 —— 死码最坏的地方不是占地方，
  是它**会被当成契约**，前端照着写分支、文档照着写章节。

### 5.3 前端架构

类型链路是单向的，只有一处真相源：

```
server/syncoj_server/schemas.py        ← 类型的唯一来源
        │  python server/tools/dump_openapi.py
        ▼
web/openapi.json
        │  npm run gen:types  (openapi-typescript)
        ▼
web/src/api/schema.d.ts                ← 生成物，不要手改
```

页面代码**只描述"这一页长什么样"，不描述"怎么取数"**：

| 文件 | 职责 |
|---|---|
| `api/client.ts` | `request`/`query`/`download`，把错误体转成带 `code` 的 `ApiError` |
| `api/endpoints.ts` | 所有路径的唯一定义 —— 服务端改路径时只需要改这一处 |
| `api/crud.ts` | 分页、信封、删除语义的公共实现 |
| `api/<资源>.ts` | **一个资源一个模块**，只有「路径 + 参数 + 返回类型」的映射 |
| `api/index.ts` | 入口，几乎全是 re-export；页面只从这里 import |
| `composables/useList.ts` | 分页、筛选、加载/错误、刷新、批量选择、可中断的请求 |
| `composables/useMutation.ts` | 执行写操作、弹提示、刷新列表、管理按钮 pending 态 |
| `components/` | `PageShell` / `DataTable` / `ConfirmByNameDialog` / `FormDialog` |

新增一个资源 = 一个资源模块 + 一个页面（外加在 `index.ts` 里加一行转出），
而不是再抄一遍 loading/error/分页/轮询。这是上一版前端的真实问题：每个 view 都
手写了一遍同样的十几行，于是加一个入口的成本高到没人愿意加。

> 拆开而不是堆在一个 `index.ts` 里，是为了让"这个资源有哪些动作"一眼能看完。
> 十几个资源的七十七个方法挤在一个文件里时，**漏接一个入口**和**看漏一行**是
> 同一件事 —— 而"很多功能没有入口"正是这一轮要解决的用户诉求。

#### 界面文案：只留动作、后果与实时数据

页面上**禁止**出现声明式/解释式语句。允许的只有这几类：

| 允许 | 例子 |
|---|---|
| 标题、标签、按钮、状态、表头、placeholder | 「统一密钥」「已签名」「sha256」 |
| **一句话**操作指引 | 「在每台空机器上跑它。」 |
| **破坏性动作的后果** | 「会删掉统一注册密钥与本机凭据。」 |
| 服务端原文错误、实时数据 | `detail` 直接显示，不加工成第二种说法 |

**删掉**的是成段的说明文：为什么这么设计、这两个概念不是一回事、机制怎么运转、
「上传不等于铺开」这类劝告 —— 它们属于文档（DESIGN/README），不属于界面。
判断标准不是"这句话有没有用"，而是**"站在机器前面的人此刻能不能据此动手"**：
不能动手的解释句一律删，能动手的后果句留下（后果句少了更危险 —— 删东西之前
必须让人知道会丢什么）。

界面上出现过 `**已铺开**` 这种 Markdown 语法，所以现在有一条 AST 守卫：
面向用户的字符串里不许出现 Markdown 标记（`server/tests/test_errors.py` 那一套
连同前端文案一起把关）。

### 5.4 删除语义

判断标准是"删掉之后还有没有人需要它"：

- **结构性数据**（名单/场次/选手/机器/题目）→ 硬删除，而且**确认方式是输入名称**
  （`confirm` 必须逐字等于 `player_no` / `slug` / `name` / `hostname`），
  校验在服务端做，不只是前端弹窗。用"是否确定"的弹窗在连续操作里会被手指
  肌肉记忆点掉，打名称不会。
- **产物性数据**（代码文件/下发资产）→ 软删除留墓碑，`?include_deleted=true`
  可见；导出**默认包含已删除的代码**，因为考场现实是"选手确实交过，只是后来
  被清了"，成绩复核时这份历史比干净的数据重要。

### 5.5 下发资产一律是文件，不解压

题面与样例本身就是 zip，服务端**只负责搬运字节**，不打包也不解压：选手或
评测机自己解压。

**唯一的例外：就地给 zip 打密码 / 改密码。** 教师会想"这一场的题面换个密码"，
而"回自己机器上重新打一个包、再上传一遍"纯属仪式，所以这一件事由服务端做
（`services/zipcrypto.py`，自写的 ZipCrypto 写实现；**读那一半仍然走标准库**，
好让"我们写出去的包能不能读回来"由独立实现判定）。四个后果跟着定下来：

* **与"在线改正文"同一套语义**：同一个 asset id 换掉 `sha256`/`size`，并把该资产
  已完成的下发目标重排回 `PENDING`、续传偏移清零（理由与上面三条完全相同）。
* **库里没有单独的密码字段**：密码只存在于自动生成/更新的那份 `password.txt`
  文本资产里，教师随时能读回来、也能像别的资产一样下发。审计事件里**不写密码** ——
  写了就等于服务端多存一份明文，而它本来只需要在教师手上。
* `password.txt` 是**单件语义**，所以是"更新同一条"而不是每次新建：否则改一次密码
  就多一条同名文件，列表上很快躺着几条，而教师没有依据判断哪份最新 —— 发错的那次
  学生看到的就是"密码不对"。
* 用 **ZipCrypto** 而不是 AES：学生的打开方式是 **Archive Manager**（GNOME
  file-roller），AES 的包它直接说打不开。所以口径只能是**挡得住随手翻看，挡不住
  有心人**（`password.txt` 自己也是明文，真要看的人一定看得到），绝不写成"安全加密"。
  密码按 UTF-8 编码；不支持 ZIP64（>4GB / >65535 条目，超出给 400）。

这条约束换来的是服务端对压缩格式的**零第三方依赖**（只用标准库 + 上面那份自写的
ZipCrypto 写实现），也换来"落盘字节与教师手里那份逐字节相同"这个可验证的性质。

**纯文本资产可以在线上改正文**（`GET|PUT .../assets/{id}/text`），因为"改错别字要重新
上传一份"是纯粹的仪式。三件事跟着定下来：

* 资产是内容寻址的，所以"改"是**同一个 asset id 换掉 `sha256`/`size`** —— 不是新建一份、
  也不是"改个标签"（改名是另一条路：换标签不动内容）。两个入口对已经落到机器上的文件
  后果完全不同，合成一个的话回执照说不清。
* 改完必须把该资产**已完成的下发目标重排回 `PENDING`，并把续传偏移清零**。tick 只对
  `PENDING/READY` 派活，已完成的不会再派 —— 不重排就是"选手页显示新正文、机器上还是旧
  文件"；不清零偏移则是拿旧文件的偏移去续新文件，**落出来一份坏文件**。
* "能不能在线改"由**服务端**算成一个布尔发给界面（判据是扩展名白名单 + 体积上限，且只看
  元数据不读盘）；真正的关卡在读写接口里：必须能按 UTF-8 解出来，否则回 400 而不是把一段
  乱码送到考场机器上。

### 5.6 两个免登录页面

管理界面之外还有两页，**故意免登录** —— 它们的使用者手上不可能有管理凭据：

| 页面 | 谁在用 | 身份怎么确定 |
|---|---|---|
| `/install` | 教师，站在还没装 Agent 的机器前 | **不需要身份**：它只展示"从哪儿装、装哪个版本、怎么核对" |
| `/player` | 选手，在考场机器上 | **服务端按来源 IP 认机器** → 配对到的人 → 场次 → 该选手 |

`/install` 里的地址用**当前页面的 `origin`**：教师是从某个地址打开它的，那个地址就是从
局域网真的可达的地址。所以它不需要服务端"告诉我我是谁" —— 那个接口要鉴权。
没铺开任何版本时它不给安装命令，只给一句"去铺开"的可行动指引。

`/player` 的身份链条是「机器 → 人 → 场次里的选手」，与 `/tick` **共用同一个解析函数**
（../design/04-server.md §4.6 的 `resolve_machine`）。这是一条硬要求：两条路径各写一套的话，就会出现
"tick 里这台机器能干活、这一页却说它没有场次"这种自相矛盾，而现场没法解释。

匹配不上时（Agent 没起来、教师用自己的笔记本打开）才给一个**手填场次 + 考号**的兜底
入口。**不用 URL 参数预填**：那会让"这一页显示的是谁"取决于一个可以被随手改的链接。

这一页只给三样东西：**考场公告**、下发给他的文件清单、以及身份卡。**不含代码、不含成绩、
不含别人** —— 有测试盯着这三条，其中"别的选手的资产不许出现"是真的会红的那一条。

页面上从上到下是**场次卡 → 考场公告 → 下发文件**。公告排在**场次标题下面**而不是页面
最顶上：公告是"这一场"的话，先有场次再有公告才读得通；反过来会让人先看到一段话、却不
知道是哪一场考试。

场次卡上还给出**开考与结束时间**（留空就是"不限"）：到点之后服务端会拒收文件，而选手
是唯一一个需要提前知道这件事的人 —— 让他自己看得到"几点结束"，比让他猜"为什么交不上去"
好。时间按服务端存的那个时刻原样下发（UTC ISO），由浏览器按本机时区显示，与教师在管理
界面里填的那个钟点一致。

公告**不是另配一处文本**，而是"下发文件里的那一份 `NOTICE.md`"：教师在「文件下发」页写
一个 `NOTICE.md`、再照常「下发」，选手页就把它的正文显示在「考场公告」里。理由与 ../design/05-api-and-frontend.md §5.5
同源 —— 公告和别的下发文件本来就是同一件事，另设一个"公告字段"等于让教师写两遍，还要
额外解释"这两个地方哪个作数"。判据是**本场 + 发给他本人**的下发记录里 basename 大小写
不敏感地匹配 `notice.md`，有多份就取最后下发的那一份；非 UTF-8 与超过 64 KB 的跳过并记
一条日志（读不出来就说读不出来，不要显示半截乱码）。

正文按 **Markdown 渲染**（`marked` + `DOMPurify`，见 `web/src/utils/markdown.ts`）。
曾经的理由是"为一段公告装一个 Markdown 库不值得，`##` 也看得懂"—— 这个判断被现场推翻了：
教师写的就是 Markdown，原样显示出来是一堆符号，而"公告看起来没排过版"会被当成系统不认真。
消毒那一步不能省：正文是教师从别处粘进来的，`<img onerror=…>` 这类东西会把考场机器上的
这一页变成任意脚本的宿主。

渲染开的是 **`breaks: true`**（GFM 行为），不是 CommonMark 默认的"软换行合并"：公告是在
一个纯文本框里写出来的，写的人未必在想 Markdown 语法 —— 他写下两行、就该看到两行。关掉
它等于把上一版 `pre-wrap` 的保证偷偷去掉，而症状（"我一行一条写的，显示成一整句了"）
只会被当成"渲染错了"。

**不用"从题目模式推导保存规则"**：服务端不知道每台机器的 `scan.roots` 与文件名前缀，
推导出来的"把代码存到 X"在现场很容易是错的 —— 而一条错的操作指引比没有指引更坏。

### 5.7 公开端口：默认 80，只放这两页

考场机器上的地址就是 `http://10.0.0.5/` —— 浏览器对 http 默认走 80，教师连端口都不用敲。
所以服务端**默认再开一个监听**（`SYNCOJ_PUBLIC_PORT`，默认 80）：

| 端口 | 上面有什么 |
|---|---|
| `--port`（默认 8000） | 全部：管理界面 + 三套 API + `/docs` |
| `SYNCOJ_PUBLIC_PORT`（默认 80） | 只有 `/install` 与 `/player`；管理端、`/docs`、`/openapi.json`、`/healthz` 一律 404 |

`SYNCOJ_PUBLIC_PORT=0` 关掉第二个监听（`0` 是哨兵：留空等于没设，会退回默认的 80 ——
"关掉"这个第三态在环境变量里表达不出来，见 `config._env_opt_int`）。

**为什么不用"同一个端口按路径分"**：那样学生敲进来的这个原点上就有登录框，还有一张接口
地图 —— `/docs` 不需要登录就能列出全部管理接口。

**为什么门禁是黑名单**（挡 `/api/v1/admin`、`/docs`、`/redoc`、`/openapi.json`、`/healthz`），
而不是"只放行这两页的白名单"：白名单漏一条的后果是**这两页悄悄坏掉**（现场看到的是白屏、
转圈或一段 HTML，没人会想到是端口门禁干的）；黑名单漏一条的后果只是多暴露一个接口，而
那些接口自己还有 `require_admin` 兜着。两侧都会漏时，宁可漏在"多一道鉴权门"那一侧。

被挡掉的接口回 **404 而不是 403**：这个端口上**没有**它，不是"你不配" —— 后者等于顺手
指路"管理接口在别处，去另一个端口试试"。

**"这个请求是从公开端口进来的吗"由服务端在启动时写进 `app.state.public_port`**，判据是
"真的在那个端口上听着"，不是配置里写的数字。两个理由：

* `serve` 绑不上 80 时会**降级**（只留管理端口，并打印两种修法）。降级之后 80 上没有任何
  监听，也就不该有请求被当成公开端口 —— 否则一台绑不上特权端口的服务端会顺带把自己的
  管理界面一起关掉，而现场只看到"管理界面 404"。
* `TestClient` 的默认地址端口恰好就是 80。判据若取配置默认值，整个既有测试套件会在
  一瞬间全部被误判成"来自公开端口"。

**前端怎么知道自己在公开端口上**：服务端在公开端口返回的 `index.html` 里注入
`window.__SYNCOJ__={"publicOnly":true,"adminPort":8000}`（见 `web/src/publicMode.ts`）。
前端据此把默认路由和兜底路由都压到 `/player`，并且**不去碰鉴权状态**（那个接口在这个端口
上是被挡掉的）；`/login` 也送到 `/player` —— 这里没有登录入口，给访客看一个登录框只会更
困惑。不让前端自己数端口：http 的 80 在浏览器里 `location.port === ""`，而且那等于把同一
个事实定义两遍。

注入里的 `adminPort` 是给**装机命令**用的：命令里那个地址会被写进那台机器的配置、从此
长期使用，所以它必须指向 API 端口，而不是教师恰好打开的那一页所在的端口 —— 公开端口是
个"方便用的"端口，可以关掉。主页名仍取当前页面的：那是"从局域网真的可达"的真人证据
（../design/07-ops-and-install.md §7.3 那三条来源的排序）。
