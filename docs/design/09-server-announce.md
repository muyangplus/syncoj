## 11. 服务端主动通告（提案，未实现）

> **状态**：已实现（2026-11）。结论：**可行，但只能做"加一条更快的路"，不能替掉 Agent
> 自己问的那条路**；理由见下面「为什么不能只靠它」一小节。报文与规矩见
> `reference/protocol.md` 的「服务端主动通告」一节；取舍记在 ADR-0015。
>
> 与下文设计的两处出入：① `whoami` 签的是**服务端自己认定的**对外地址，机器切到签名里的
> 地址（而不是通告里的那个），这样请求被转发给真服务端时也只会指回真服务端；② Agent 自己
> 探测的阈值**没有放宽**：通告在 ufw 打开的机房里完全收不到，放宽只会让那些机房变慢。

### 11.1 想要什么

现在（§7.3）是**机器问、服务端答**：包里没带地址、或者连续几轮连不上时，Agent 往局域网
广播一个探测，服务端用发布私钥签名应答。提议反过来：

* **监考端（服务端）上线时广播一次**"我在这儿，地址是 X"；
* **考试端（Agent）一直听着，听到就响应一次**（用这个地址连上来），**不主动扫描**。

动机：服务端换了 IP（DHCP、换了一台机器当服务端）之后，现在要等每台 Agent 连续失败
三轮（约 35 秒）才各自去问；通告的话服务端一上线，50 台机器在一两秒内就全部转过来，而且
平时局域网里没有 Agent 发出的探测包。

### 11.2 协议草案

**通告**（服务端 → 子网广播，UDP，固定端口，与发现端口分开）::

    {"syncoj": 1, "kind": "announce", "url": "http://10.0.0.5:8000",
     "key_id": "<公钥指纹>", "boot_id": "<本次启动的随机数>"}

**不签名**，或签了也不信它 —— 它只是一个**线索**。Agent 收到后：

1. 过滤：`key_id` 不是自己信任锚的指纹 → 丢弃（隔壁考场的服务端）；`url` 与当前在用的
   相同 → 丢弃；同一 `boot_id` 处理过 → 丢弃；按来源限速（每分钟最多认真处理一次）。
2. **到那个地址上做挑战应答**：`GET <url>/api/v1/agent/whoami?nonce=<Agent 现生成>`，服务端
   回 `syncoj-announce-v1\n<nonce>\n<url>` 的签名（与 §7.3 同一把发布私钥、换一个版本前缀
   做跨协议隔离）。验过才切换。
3. 切换只在进程内生效，不写回 `agent.ini`（与 §7.3 的"运行时重新发现"同一条规矩）。

为什么挑战应答而不是给通告签名：通告是**服务端单方面发出**的，Agent 没有机会给它一个随机数，
签名再强也挡不住**重放** —— 攻击者录下一条真通告，等那个 IP 被 DHCP 分给自己的机器后再放出来，
50 台机器就会把统一注册密钥、选手代码送过去。带时间戳的签名要求考试机时钟准，而还原卡
机房的时钟常常差几小时。挑战应答让"这个地址此刻真的握着私钥"成为切换的前提，通告本身
被伪造、被重放都只会浪费一次 HTTP 请求。

**服务端什么时候发**：启动后前 10 分钟每 30 秒一次，之后每 5 分钟一次；管理界面加一个
"召集机器"按钮立即发一次（这就是"监考端广播问一次"）。报文 < 200 字节、无应答（Agent 的
响应是一次 HTTP 请求，不是 UDP 回包），没有放大面。

### 11.3 为什么不能只靠它（"不主动扫描"做不到彻底）

* **开机顺序**：通告是瞬时的。服务端先开、考试机后开（考场的常态），机器错过了那一次，
  要等下一次周期通告。所以周期通告必不可少 —— 那时"服务端广播一次、学生端响应一次"实际
  变成"服务端一直在喊"，只是喊得很稀。
* **装机时**：安装器跑的那几十秒里不会恰好有通告；而包里没带地址时安装器必须当场拿到地址
  （要写进 `agent.ini`、要注册）。安装器那一次主动问**必须保留**。
* **听不到的网络**：Ubuntu 的 ufw 打开时默认拒收入站 UDP；有些交换机隔离广播。机器主动发出
  的探测是出站流量，不受 ufw 默认策略影响；通告是入站，会被挡。这类机房里通告完全失效，
  只能靠机器自己问（或者 `--discover-address` 单播）。
* 所以推荐的终态是：**通告是主路径、Agent 探测降为兜底**（例如连续失败 10 分钟才问一次，
  而不是现在的 35 秒），而不是删掉探测。

### 11.4 Agent 侧的代价

* **常驻监听一个 UDP 端口**：选手账号能绑 >1024 的端口，沙箱的
  `RestrictAddressFamilies=AF_INET AF_INET6` 允许 UDP，不用改单元。但这是 Agent 第一次
  **对外暴露一个入口** —— 输入一律按不可信处理：限长（512 字节）、只认 JSON 里那几个键、
  限速，处理逻辑只是"去某个地址发一个 HTTP 请求"，最坏结果是被人诱导去访问局域网里的某个
  地址（SSRF 的一个弱化版：只能 GET 一个固定路径，且不带凭据 —— 挑战应答请求**不带**
  Bearer 令牌，验过签才用凭据连）。
* **线程**：主循环是单线程的，监听放一个守护线程，只往一个线程安全的"候选地址"槽里塞东西，
  主循环每轮开头看一眼。不改变"Agent 近乎无状态"的性质。
* 选手在本机上伪造通告：被挑战应答挡住；本机选手能做的最多是让 Agent 每分钟多发一次失败的
  HTTP 请求。

### 11.5 落地顺序（如果做）

1. 服务端：`/api/v1/agent/whoami` 挑战应答端点（不鉴权，签名复用 `services/discovery.py`
   的规范化文本风格，新前缀）；周期通告任务；"召集机器"按钮。
2. Agent：监听线程 + 候选地址槽；切换前挑战应答；探测兜底阈值放宽。
3. 测试：伪造 / 重放通告不切换；`key_id` 不符不切换；挑战应答失败不切换；通告与探测同时
   存在时不互相打架；systemd 245 冒烟里加"服务端换端口重启后机器自己转过来"。
4. 文档：改写 07 的 §7.3；协议参考加报文；ADR 记"为什么不签通告、为什么保留探测"。
